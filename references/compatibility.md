# 模块兼容与图像工具

## 指令范围

2026-10-21合并时各旧 GUIDE 保留正文并加作用域提示。1.2选择性调整taste v2风格默认；1.4继续修正已证实的预设、改造、图像与Stitch正文冲突及机械配额，工程代码和已有修复保留。taste v1明确兼容线、Stitch DESIGN.md原模板、检索数据/脚本和许可保持原件；历史保留记录仍保留历史身份。模块frontmatter不作为独立注册入口。正文中的 “this skill”“always”“must”等只作用于入口已选择的模块与当前阶段，不据此把一种产物扩成所有产物。表内旧名字与旧目录名均指包内 GUIDE，没有旧ID独立兼容壳。

用户当前需求和既有长期指引的权限、品牌、内容及技术约束保持优先。真实性、必要功能、可访问路径、减动效与工程修复继续生效；字体/图标黑名单、数字配额、色板、圆角、布局和装饰不能仅因预设措辞就升级为全局硬门槛。用户现有DS、批准截图与品牌字体应保留，只有授权改这些部分时调整；当前授权范围内可逆的视觉选择无需用户逐项点名。依赖须核实实际项目，不因示例声称可用而假设已安装；缺一个库也不等于该表达能力不可用，先考虑原生、现有依赖或合适替代。随机选择可作创作手段；声称运行随机程序时须有真实输出。

## 选择一个产物，再选择风格

Impeccable 是审稿与精修方法，UI UX Pro Max 是可检索的资料；两者都不是附加风格，不叠加其全部默认。单入口按当前问题选择相关参考与查询。新建/完全重构且视觉开放时，先走[方向形成](../modules/art-direction/GUIDE.md)和[概念审稿](../modules/impeccable/references/concept-review.md)，先比较方向再选实现参考；既有DS延展和小修不补做这条链。只审美评审/审计时不修改代码、不持久化设计规范；后端或纯逻辑修复不因提到UI库就触发视觉改造。

UI UX Pro Max 的检索与数据在同一包内，默认只向标准输出返回建议。按[检索模块](../modules/ui-ux-pro-max/GUIDE.md)从技能真实绝对路径调用，不在项目根猜测 `scripts/`，不注册独立入口。已有DS/截图优先，应用界面忽略生成器可能返回的营销结构。开放方向的新建/完全重构在锁定方向前实际做聚焦查询并记录取舍，允许联网且可访问时查看有差异的外部视觉参考；既有DS、精确参考和小修只针对知识缺口查询。不能把命中结果当作已验证方案，也不能把校准网站当作用户批准的精确参考。

- **已有参考**：检查原图并提取颜色、字体、布局和组件，再实现。裁切或放大仅用于检查；生成图不能作为原参考的证据。
- **新图像参考**：仅新参考路线采用 image-to-code 的分节生成、检查、实现顺序。只要图像时使用 web 或 mobile 模块并交付图像。随后用户要求实现时才转图到代码或既有项目实现。
- **直接代码**：明确 DS、小修和无新增参考需求的改动直接实现；没有强制图像或装饰配额。
- **现有改造**：审计检查表用于识别实际问题，按任务范围修改；授权完全重构且无已批准精确参考时，先形成方向，保留范围由用户请求决定，不把旧布局当硬约束。现有日期、价格、数据、评价和文案保持真实；示例内容须明确标注。改造流程可使用用户选择的一种风格，不叠加 taste v2 与另一预设的全部硬规则。
- **品牌板**：一张图可以包含品牌系统多个面板；web 的每节一张规则不作用于品牌板。先复用提供的 logo/色板，明确授权重塑才设计相应新元素。
- **Stitch DESIGN.md**：将已选系统写成语义令牌、精确值和组件行为。模板的高方差、字体、图片或动效只是待适配内容；用户现有 DS 与静态需求仍优先。写本地 DESIGN.md 不要求登录；向远程 Stitch 提交才需要可用连接和相应任务授权。

图像模块与视觉预设按当前产物使用。品牌板图像不是原生矢量 logo 文件；移动概念图不是可运行 App；参考图不是浏览器验证。没有相应产物或操作证据时保持对应验证层级。

## 动效与预设冲突

开放方向须将[材质、空间与运动](../modules/art-direction/references/material-space-motion.md)作为可采用或拒绝的表达考虑；不强制材质、3D或动画，也不把某次任务拒绝的颜色/字体变为全局禁令。已选运动在正常浏览器模式实际操作并观察过程与终态；冻结截图仅支持外观，减动效可用性与正常运动体验分别验收。局部修复和无动画DS维持原范围。

方向形成阶段比较候选，交付界面应用协调的表达系统，不必套用命名预设。协调不等于全页同色、同一材质或所有章节同构；可以按内容角色组织有关系的明暗、色彩与材质变化。不同模块的工程方法可按需复用，不把互相冲突的风格默认同时变成硬要求。CTA、中心布局、叠层和排版依据真实内容、批准系统与已选方向，Stitch应转译这些决定而不是另换一套审美。

明确 no-animation 与 `prefers-reduced-motion: reduce` 都显示可读静态终态。保留本机已修复的 GSAP ScrollTrigger 清理、实例隔离、外层 pin / 内层 transform、容器非负滚动距离与 refresh 重算；不把旧样例中的 `transition-all` 或必须进场语句作为覆盖已修规则的理由。移动端滚动与键盘焦点按实际组件验证，不把可用横向面板与整页意外溢出混为一谈。

## 图像工具绑定

需要生成或编辑位图时，读取本宿主实际可用的系统 `imagegen` 指引，并调用其图像生成工具。这里保留的创意提示词、品牌板模板、网页分节规则和移动框构图是内容层，不构造不存在的工具参数或外部服务。

1. 先确认实际工具 schema；把尺寸和构图要求写入提示词，只有 schema 支持时才传尺寸参数。输出像素与请求不一致时报告实际值和影响，不承诺未支持尺寸。
2. 新生成不携带无关参考。编辑本地图像先查看，按实际 schema 传已查看文件路径；对话图像用宿主规定的引用方式。透明背景与已有透明度按用户要求处理。
3. 缺必要品牌资产或待编辑原图时说明缺项并取得素材；已有素材不重复索要。工具不可用就交付允许的提示词或实现部分，清楚标注图像未生成，不把文本称为图像成果。
4. 输出使用宿主原生图像回传或真实本地文件预览。web 模式每节逐张完成，mobile 按屏幕/流程方案完成，brandkit 按板式完成；不因当前包覆盖多个模块而扩大生成数量。

本包不新增付费服务、联网安装、发布或发送授权。图像调用、代码构建、浏览器检查、远程 Stitch 执行各保留真实证据；本包的静态整合检查不等同于业务效果提升。
