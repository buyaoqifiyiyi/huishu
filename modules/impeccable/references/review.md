# 先审稿，再核实

由 Impeccable 的 critique、audit 和 operate 方法改编。适用于网页和前端；不是其完整命令实现。审计请求只读，不写代码、持久化快照或附带修复。

## A：形成设计判断

先查看目标页面及主要动作，在接触机械检查结果前记录：

- **产品辨识度。** 去掉名字和 logo，这套结构、图像和语言还能表达当前产品吗？哪些选择来自内容，哪些仅因模板方便？后台熟悉的导航、系统字体和密度也可恰当，不以“不同寻常”代替好用。
- **读图与任务。** 眯眼看页面时能否辨别主焦点、次焦点和分组？用户知道下一步、当前状态和完成结果吗？作品集是否让作品先出现，文章是否让阅读连续？
- **负担。** 查找重复信息、互相竞争的动作、无解释术语、跨屏记忆、为同一决定来回开面板、相同动作不同表现。选项多只提示检查分组和识别成本；不把“最多四项”当科学定律删掉必要导航、表格或功能。
- **体验曲线。** 初次进入、等待、提交、出错、空结果和结束处的感受是否有断层？高风险动作是否有清楚后果和恢复路径？没有实际观察的状态标未验证。
- **受众视角。** 根据真实任务选择首次用户、频繁用户、手机分心场景或键盘/辅助技术使用场景中的相关视角，实际走主动作并指出具体阻碍；角色推演不是用户研究数据。

### 咨询与转化路径：按需走查

仅在访问多但咨询少、客户不信任，或营销页/服务详情的咨询与转化路径审计中使用。后台密度、字号/颜色小修、精确参考实现，以及没有咨询目标的作品画廊沿原短路径。

先从真实广告语、搜索词、入口链接或用户提供的客户资料提取**到达意图**，写明依据来自哪里；未知部分标为假设，不推断依恋类型、国籍心理或编完整人设。资料已在上下文中就复用；缺资料仍可给有限的专家判断，但不能称为真实客户反应。

沿代表性任务，选择与当前问题相关的具体页面段落或状态，记录：**到达意图及依据 → 此刻需回答的疑问 → 当前可见证据 → 信息或行动阻碍 → 下一步动作**。证据须来自实际查看的页面/截图与可核对事实；未观察的状态标未验证。下一步可以是继续理解、查看细节或咨询，不要求每屏都有 CTA，不固定设备、滚动距离、双声部或结果数量。只有真实受众差异会改变建议时才对照。

将建议接回下文的“位置 → 证据 → 影响 → 建议 → 验收”：指出具体段落如何补上承诺所需的证据或行动条件，并用相同到达情境核对相关段落及路径。分清页面观察事实与角色假设；这是专家走查，不是用户研究、真人测试或已证实的转化效果。没有业务数据时不报告转化增长数字，不因此新增研究模板、独立门禁或修改授权。

保留 2–3 个有效设计决定及理由，挑出最重要的 3–5 个问题；无问题时不凑数。

### 营销页策略补漏（按需）

新建营销页或相关咨询审计中，补查当前尚缺的关系：访客从哪里来、页面承诺是否接得上、当前受众为何相信、下一步能得到什么，以及哪些真实条款降低行动阻力。一个具体投放落地页通常围绕主要行动；多任务首页、后台和作品画廊按实际用途组织，不把“单一CTA”变成全站规定。证据应靠近所支撑的主张，疑问与FAQ来自实际阻碍，不固定章节数量和顺序。

价格、量化收益、客户评价和取消/试用/退款承诺只能来自已确认资料；缺失时标待补或给明确标注的示例，不用看似真实的人名、客户logo或零碎数字制造证明。已有资料足够就复用，不额外启动一轮模板访谈。此补充选择性改编自[Elaya落地页策略](https://github.com/elayadesign/ai-design-skills/blob/a2735a3eaf092eaaffb6dc17df25de33ef3bd048/skills/landing-page-design/SKILL.md)，归属及排除项见[整合记录](../../../references/integration-20261026-elaya.json)。

## B：核对实现与行为

用项目已有检查、源码、计算样式与宿主浏览器工具，核实以下与任务相关的项目。工具缺失写清缺项，不下载 Impeccable 或制造假扫描结果。

| 维度 | 查什么 |
|---|---|
| 可访问性 | 语义和标题结构、可读名称、表单标签与错误、键盘顺序/陷阱/焦点、对比度、色彩之外的信息、静态/reduced-motion路径 |
| 响应式 | 窄/中/宽容器的重排、真实长文/本地化、放大、覆盖层裁切、粘性元素遮挡、意外整页溢出、适用的触摸目标和手势 |
| 状态与主题 | 默认/交互/禁用/加载/空/失败/成功等实际可达状态，语义色一致性；项目已支持的主题才检查切换，不额外实现暗色模式 |
| 性能 | 实测可见的卡顿、布局位移、图片尺寸与载入、已证实的重复工作或多余资源；不凭组件存在就要求 memoization |
| 系统一致性 | 同角色字号/间距/色彩/组件是否漂移，真实证据是否被装饰数据取代，导入与资源是否实际存在 |

核查 WCAG 2.2 AA 时，区分以下判据与更高的项目设计目标：

- **文字对比度。** 普通文字至少 4.5:1，符合标准定义的大文本至少 3:1（通常至少 18pt 或 14pt 粗体，不能只因元素是标题就视为大文本）；计算值不向上四舍五入后判达标。非文本控件与例外另按适用条款判断。依据：[SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
- **指针目标。** SC 2.5.8 的 AA 尺寸条件为至少 24×24 CSS px，不足尺寸还要检查间距、等效控件、行内、用户代理样式或必要呈现等例外。间距例外检查以各小目标边界框中心放置直径 24 CSS px 的圆，不与其他目标或其他小目标的同类圆重叠；不能只看控件之间有一点空白。44×44 可作为更易操作的设计目标，不能仅因未到 44×44 就判 AA 失败；AAA、平台规范和项目更高要求另核。依据：[SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

静态发现先核实上下文；源码有媒体查询不等于手机操作通过，截图有焦点样式不等于键盘路径通过。视口模拟、合成触摸和真机分别说明。

## 合成发现

将 A 和 B 对应，确认真正影响用户的原因。工具发现但视觉上合理的例外说明理由；整体设计判断和可重复的缺陷分开。无需为了独立判断强制增加子代理：当前宿主与用户允许时可独立评估，否则按 A→B 顺序执行并如实描述方法，不冒称上游双代理 critique。

每条问题写：**位置（页面/组件/选择器/文件）→ 可见或可复现证据 → 用户影响 → 具体建议 → 如何验收**。

| 优先级 | 实际影响 |
|---|---|
| P0 | 核心任务阻断、数据丢失或严重误导状态 |
| P1 | 显著困难、主要路径不可访问、重要状态或恢复缺失 |
| P2 | 有可行绕路的局部问题，影响扫描或完成效率 |
| P3 | 细节精修，实际用户影响小；少量列出即可 |

默认不以主观总分装作客观测量。用户要求结构化评分时，可评估十项启发式：状态可见、贴近用户语言、控制与退出、一致性、预防错误、识别胜于记忆、效率、必要信息与层级、错误恢复、帮助。逐项用 0–4（阻断→严重缺口→部分满足→良好有小缺口→充分证据支持）并附证据；不适用注明原因，未观察记“未验证”，不按满分算。不适用或未验证项排除后，分母只计实际评分项×4，注明这是人工评估。

交付先给整体判断和最高影响项，再给具体问题、值得保留的部分、已验证与缺项。已有改造授权且方向明确时继续实施；只要求审计就在审计结果处完成。不强制末尾再询问一次优先级。
