# 精修、简化与增强

由 Impeccable 的 polish、distill、quieter、bolder 和 craft-floor 改编。保留真实内容、功能和用户确认的品牌/设计边界；模型为当前任务自行选的视觉仍可修正。按请求区分局部精修与授权重设计，不把所有流程默认收窄成降噪或微调；也不借增强表达擅自改变未授权品牌或删除业务能力。一次只选解决实际问题的流程，不把四个流程依次全跑。

## polish：让整条路径同样完成

读现有系统和相邻流程，再将漂移归类：缺必要令牌、没用已有共享组件、局部缺陷或概念/流程不一致。修最小正确原因；一个例外不值得新建组件系统。

按影响顺序处理：

1. 核心动作、误导状态、数据完整性与不可访问路径。
2. 实际会出现的加载、空、失败、成功、禁用和权限状态。
3. 流程、层级、响应式与系统一致性。
4. 视觉和动效细节，以及本次改动产生的冗余。

检查整个“进入→操作→反馈→恢复/结束”路径，不把一个角落打磨过头而遗漏主动作。对齐项目网格、角色与语义色；检查真实长度、图像比例与位移、图标家族/笔画/基线、控件和覆盖层。操作文案说明动作，错误说明问题与恢复；不要编造宣传证据或修改事实来让画面更好看。

动效可服务于状态因果、空间连续、叙事节奏或品牌氛围；在本次授权范围内决定，保留用户 no-animation 和 reduced-motion 静态终态。局部精修不自动扩大成长开场、滚动劫持或依赖安装。保留原包已有动效清理与实例隔离修复。

同尺寸比较前后，重走范围内主要动作与键盘路径；有必要时检查触摸。审查 diff 移除意外大范围格式化、本次产生的死代码和重复值。已通过的检查没有新变化无需重跑。

## distill：移除阻碍，不删掉必要能力

先说清主要目的、完成目的必需的信息和动作。区分任务固有复杂性与界面附加复杂性：删后者，组织前者。看重复信息、过多同权动作、无意义容器/描边/阴影、相近样式变体、跨屏来回和无帮助的步骤。

按影响选一种最小改法：合并重复说明、恢复主次、将低频选项清楚分组或渐进披露、减少不承载意义的层级、复用共享样式。所有原必要能力仍能找到；不机械套“一套字体/四个字号/一条竖列/移除侧栏”。法律、风险、价格、数据和关键标签不作为“啰嗦”直接删。

验收：用户仍能完成原任务，少记信息、少绕路，必要选项和恢复路径仍可发现。删除了可见入口时明确它的新位置与理由，不声称未实测的速度提升。

## quieter：降低噪声，保住辨识度

找出过强来源：过多饱和色、过多同权粗字、大面积高反差、装饰、层叠、动画或所有元素都巨大。先决定哪一个焦点必须留下，再减弱围绕它的竞争；产品工具通常重点在清晰的状态和稳定层级，品牌页面可以保留合适戏剧性。

可减少无目的色彩/装饰/阴影、收敛粗字与大小、理顺间距、减少层叠和装饰动效。每项改动都要保持文字与控件对比、可操作线索、主次和品牌特征；不将所有文字做小做浅，不以全灰或统一字重假装克制。具体色度、缓动和留白由实际系统决定，不照搬固定百分比。

验收：阅读更连续、核心动作易找、没有被噪声淹没，也没有失去关键区分与操作线索。

## bolder：按保留范围增强表达

先确认指定目标和外围保留范围。判断发平来自角色对比不足，还是内容载体、图像、材质、空间或运动没有承载表达；不要先认定新表达没有价值。既有已批准品牌/DS沿用其语言，授权开放的视觉改造则接[方向形成](../../art-direction/GUIDE.md)，不被模型刚选的旧方案锁住。

选择与内容相关的强调并做完整，保留清楚主次；可增强类型对比、构图节奏、真实作品/产品证据，以及合适的材质、空间与运动。移除文案后看结构，是否仍能表达该区块的内容角色？图像可以承担证据、解释、叙事或氛围作用；不得把概念图伪装成事实，缺素材写清所需工作，不放无关照片凑数。

局部任务中不擅自替换已批准系统、越界改邻居或改真实声明；当前已授权视觉范围内可增补需要的色彩、字体、材质、阴影和交互。需要改变范围之外的品牌或功能时再确认；不要为已授权的可逆创作逐项索要许可。

验收：范围外无变化、行动惯例和真实内容仍成立，目标的表达收益可见；不能把所有元素变大、变亮、会动当作增强，也不能以克制为理由一律排除这些手段。
