# 排版、空间与色彩

由 Impeccable 的 typeset、layout、colorize、operate 和 craft-floor 聚焦改编。每次只选实际问题涉及的节；数值是诊断起点，服从现有 DS、语言、界面用途与批准参考，不借专项修正替换品牌。

## 排版：先定义角色，后改字号

先列出标题、正文、标签、辅助信息、数据等实际角色，以及各角色的字体、字重、大小、行高、字距、行宽和来源。检查：

1. **权威与必要性。** 哪些字体已由品牌或 DS 确认？第二字体有什么独立任务？产品工具和阅读界面一套调好的字体可能足够；不因系统字体或 Inter 出现就换掉。
2. **角色对比。** 不读文案能否分清主次？字号相邻时，可由字重、间距和色调共同承担层级；同角色跨页面保持一致。
3. **真实阅读。** 西文长文常从约 45–75ch 检查起；中文及混排按实际字宽、标点和阅读密度调整。普通网页正文可从 1rem / 16px 检查起，但不把它作为小标签、表格或平台组件的统一下限。行高适配字体、语言、行宽和对比，避免套死比例。
4. **极端与投放。** 长标题、窄容器、本地化、200%文字放大、缺失字重、回退字体和加载后的位移如何？只载入实际使用且许可允许的字体资产和字重，不为精修强制下载新字库。

实施前用一句话写清“哪些角色要拉开、哪些要稳定、阅读宽度与密度是什么”。按原令牌体系调节；数据需要时用表格数字，代码才用等宽。产品工具通常用稳定 rem 角色；营销展示字可按容器缩放，但服从真实换行。

标题可用 `text-wrap: balance`，长文可渐进增强为 `text-wrap: pretty`。浏览器不支持时保留正常换行；手动换行只放在语义短语间，并检查所有相关宽度，不以某一张桌面截图的整齐牺牲手机阅读。深色底浅字必要时微调字重、行高和字距，实际查看后决定。

验收：角色可辨、长短内容可读、混排/放大不截断、字体加载无明显跳动，确认的品牌仍在。指出计算值或渲染证据，不只说“已优化字体”。

## 空间：用关系建立秩序

先命名主要阅读/任务路径、同组元素、必须分开的组、领衔元素、密度及跨宽度变化。再看：

- **分组优先。** 相关元素近、不相关组远；先试接近性与对齐，再加边框/背景/卡片。卡片应表达可独立操作的单元或层级，不只是默认容器；合理重复与数据表不因“模板感”被拆掉。
- **节奏。** 紧凑组内间距和宽松组间间距需要对比，同一个 gap 重复全页会抹平层级。沿用已有间距刻度，有缺口才补，不新造第二套系统。
- **拓扑。** 内容等价才用等大卡片/等列；优先级不同用适当结构表达。变化不是目的；熟悉、稳定的后台布局本身是优势。
- **响应是结构。** 列、侧栏、表格、工具栏何时折叠/换行/滚动？重排后 DOM 阅读顺序与键盘顺序是否一致？同组件在窄容器里也应可用，不只依赖整页断点。
- **边界。** 检查长文、空状态、粘性元素、覆盖层、z-index与滚动容器。菜单不应被父级 overflow 裁掉；复用项目现有 popover/dialog/portal 方案，先读现有实现。

同辈距离可用 `gap` 表意；复用现有布局原语。只有实际渲染看着偏时才做光学对齐。验收用眯眼测试+真内容：主次、组关系、密度仍成立，窄/中/宽与放大路径能操作，无意外整页溢出。

## 色彩：角色和注意力优先

先看品牌承诺、语义色、主题、实际状态和背景，再选择用色策略：情绪温度、主色关系、对比范围、用色强度。没有通用“品牌色只能占10%”或“必须染色灰”的配额。

按角色检查画布/层叠表面、主次文字、行动/焦点/选择、边界、成功/警告/错误、实际需要的数据类别或色阶。最强颜色应有明确职责，别把主行动色分散到无关装饰。彩色表面的次级文字要与表面或前景协调并保持对比，不机械套浅灰；中性灰适合时可以用。暗色主题需单独设计层级，不能简单反相。

沿用项目已有色彩空间与令牌。新网页色板可以用 OKLCH 方便调节明度和色度，但既有项目不为使用它迁移全部颜色；接近黑白时检查色度，透明叠层按实际合成背景计算。数据编码结合标签、形状或位置，不能只靠颜色。

对比检查以实际前景/背景计算：普通文字通常至少 4.5:1，大字与相关非文本 UI 通常至少 3:1；焦点可见性按实际组件与适用标准核实。检查 hover/focus/selected/error、图片上文字和已有主题；禁用内容记录实际可读性，不错误宣称其与普通文本适用同一 WCAG 要求。没有对比计算工具时给出待算清单，不能仅凭肉眼宣布达标。

验收：颜色含义稳定、注意力落在目标、密集/空/错误状态仍清晰、主题各自成立，色彩之外仍能读懂信息。无需为了“更有审美”添加另一套色板。
