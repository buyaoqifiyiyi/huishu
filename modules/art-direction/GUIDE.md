# 前期方向形成 · Art Direction

> 绘枢包内工作流程，不是新 Skill、美学预设或上游运行时。先遵循[入口](../../SKILL.md)与[兼容规则](../../references/compatibility.md)。方法选自 Impeccable 固定源的 new-work、shape 与 critique，经过中文重组和宿主适配；来源与许可见[登记](../impeccable/references/provenance.md)。1.3的材质/空间/运动和时序验收为本地用户纠正驱动的补充，见[整合记录](../../references/integration-20261024-v13.json)，不冒称新增上游采用。

用于新建或用户明确授权完全重构、且没有已批准精确参考的界面。目标是在编码前形成有内容依据的方向，在成品中检查它是否成立。不要先加载 taste 全篇再用这个流程替已有默认补理由；选定方向后，taste 或其他适合的预设才作为可选实现参考。

## 1. 先确认保留范围

从用户请求、现有代码、代表页面、资产、品牌/DS和已知决定判断，不因缺少 DESIGN.md 就认定没有视觉系统。

| 当前关系 | 做法 |
|---|---|
| **preserve 保留**：按精确截图/批准设计实现、既定DS内交付，或只审计、小修 | 沿原短路由提取和执行；不做方向竞赛，不擅自重塑品牌 |
| **extend 延展**：给已有系统加页面、组件、状态或内容 | 继承其视觉语言，解决本次任务、层级与衔接；仅知识缺口做聚焦检索，不把局部新增扩大成整站重设计 |
| **replace 新建或替换**：从零设计，或明确完全重构且视觉选择仍开放 | 进入下面的前期链；完全重构仍保留真实内容、功能、明确品牌承诺及技术约束 |

已有精确参考或已定DS、小修、只审计、图像参考图、品牌板、Stitch DESIGN.md 维持入口原路线；用户明确要探索这些产物的方向时才按其任务比较。模型刚为本任务选的 taste 不属于用户不可改的品牌。单入口、最终使用一种风格，不妨碍在选择前比较不同方向。

## 2. 从内容确定要解决的事

提炼一段够用的 brief：谁在什么情境进入，最先要理解或完成什么，哪些真实内容/作品/证据能支持它，最终动作或阅读结果是什么。区分促成决定、完成任务、理解内容、观看作品的主次；保留真实文案、数据、素材和重要状态，缺少事实用明确占位，不虚构背书。

先读现有材料解决问题，只对会改变结果且无法自行确认的重要缺项提问；不固定访谈轮数、不要求先建 PRODUCT.md/DESIGN.md。记录真正约束与可自由选择部分，避免把“这个类别通常长这样”当成 brief。

## 3. 用资料扩展候选，再校准

**本地检索发生在锁定方向前。** 没有既定方向时，读取[UI UX 检索指南](../ui-ux-pro-max/GUIDE.md)，实际执行 1–2 项聚焦查询，选择本任务最需要的 product、style、typography、google-fonts 或 color 域。用2–5个英文词表达单一意图；可查询一个贴近任务的方向与一个不同的表达，不能只查完首选便称比较完成。命令从已加载绘枢的真实绝对路径调用，例如：

```text
python -B "<HUISHU_ROOT>/modules/ui-ux-pro-max/scripts/search.py" "creative personal portfolio" --domain product --json
python -B "<HUISHU_ROOT>/modules/ui-ux-pro-max/scripts/search.py" "expressive editorial typography" --domain typography --json
```

这些命令仅说明调用语法，示例行业与 editorial 形容词不是当前任务的检索或风格默认。先用真实内容和任务发现方向，再按缺口细化；不要让几次查询都预先包含同一种美学结论。核对返回域、类别、具体建议、平台与语言覆盖，记下采用和拒绝理由；命中项不是已验证方案。后台不套 Hero/客户Logo/销售联络结构，拉丁字体命中不等于中文可用。不为满足次数继续查：偏题可按检索指南改写一次，仍不匹配就记录；Python/脚本不可用时读相关CSV或项目资料并明确“未执行检索”，不安装运行时、不假造输出。

**外部视觉校准。** 在任务允许联网且工具可访问时，查看通常2–3个表达有差异的真实页面或截图，可跨相邻领域，避免全选同一模板。记录每个URL、实际看到了什么、可借的组织/排版/内容呈现原则，以及不适合本任务的部分。搜索摘要只支持发现，不能声称看过页面视觉；只取得截图就说明截图来源和范围，访问失败就记失败并使用可核实的本地参考。参考用于校准，不把外部图片、字体或文案拷入交付，也不推断素材可再分发。禁止联网或工具不可用时直说缺少此层校准，继续允许的工作，不新开聊天或新增付费服务。

## 4. 提出真正不同的方向并选定

通常提出2–3个紧贴相同真实内容和访客任务的方向。先读[材质、空间与运动](references/material-space-motion.md)，将这些表达纳入取舍。每个方向至少在以下两项上实质不同：页面拓扑/信息顺序、主导内容载体、排版角色与尺度、色彩组织、图像策略、材质/空间关系、运动叙事。不能把同一个左文右图骨架换色、换字体或改 variance 数字当成发散；也不要求强行反常或给装饰、图片、动效设配额。

每个方向用几句说明：内容如何主导、首屏先展示什么、访客怎样走到重要作品/信息/动作，材质、空间和运动分别采用或拒绝什么及原因，为什么适合本任务，以及一个真实风险。平面、静态也可成立，但不能未经考虑就复用上个任务的色板、大字和hero；已批准相同风格仍优先。必要时用小线框或现有素材草图帮助比较，不强制多图生成或额外服务。可以从观众熟悉的出版、信息图、展览或日常场景提炼结构原则；不能只给终端、纸张等外壳换皮。

依据内容辨识度、表达与体验收益、任务清晰度、可用素材、相关平台阅读和实现边界选择一条，写清其胜出原因与其他方向被拒原因。表达收益与实现代价都要具体比较；不要只因某方向熟悉、静态或编码最省事就胜出。用户已授权视觉创作/重构时，应主动选择所需材质、空间、图像和运动，不等逐项点名；缺某库先查原生能力、现有依赖或适合的替代方法，只有真实限制才降级。有已授权自主实施的明确任务时作出判断继续；只有未决选择会改变未授权品牌、事实、功能或范围时再问，不把每次方向形成都变成等待批准的仪式。用户后续选择优先。

## 5. 写下承诺，编码前审稿

在已有任务记录或简短对话中留下以下承诺，读[概念审稿](../impeccable/references/concept-review.md)核对后再实现：

- **first viewport 首屏**：指定代表视口下，真实内容的第一焦点、主张/作品/任务证据、下一步入口及下方内容线索；避免只有情绪词。
- **阅读路径**：桌面与手机分别先看什么、如何发现核心内容、如何进入详情或完成主要动作；手机不能只写“分栏堆叠”。
- **表达系统与边界**：主导内容载体、字形角色、色彩关系、图像取舍，以及材质/光照、空间层次的选择；保留什么，最需验证什么。当前创作范围内的可逆视觉实现由执行者主动决定；不把一般创作裁量误当成每种效果都要再审批，也不承诺缺实际技术/素材支持的结果。
- **关键行为时序**：需要运动时写清触发 → 状态变化/节奏 → 可操作终态，以及途中重复、离开和返回的接续；说明手机触摸/键盘替代和减动效路径。无动画仍须完整可用，正常模式则兑现选定运动；无运动时记录与任务有关的拒绝理由。

选定后只应用一种协调的视觉语言；按需加载对应预设和工程参考，用户品牌/DS、中文字体覆盖、实际对比度、原栈和可访问性优先。保留现有GSAP实例清理、pin/transform隔离与refresh重算，以及 no-animation/reduced-motion 的可读静态终态；不因前期探索拆掉这些保障。

## 6. 用成品兑现选择

在真实浏览器先以正常动效实际操作关键路径，对照[时序验收](references/material-space-motion.md#在真实浏览器中看过程)观察触发、过程和终态；按任务验证中断/返回、窄屏替代及减动效可操作路径。截图检查首屏、材质/空间呈现、内容发现和手机路径，再检查比例、相切、换行和对比度。批量检查适用的桌面/窄屏和代表状态；通常只围绕最影响结果的问题做一次有限修正，修后复核改动处。已有充分证据就收口；新失败或新修改才继续必要检查，不开启无限审美迭代。

本次任务应可核对：preserve/extend/replace及依据；实际查询/结果取舍或降级；实际查看的外部参考或未查看原因；方向差异和选择；首屏/路径/表达与时序承诺；编码前判断、成品概念/渲染及实际动态操作结论。可放已有任务记录或简短对话，不要求每次新增报告、统一数据库或固定文件树。没有浏览器证据时明确未完成成品验收；冻结截图、源码动画声明和实际过程分别标证据层级，流程执行记录不等于审美已提升。
